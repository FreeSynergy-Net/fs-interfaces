# Form catalog (ADR 0068 style, read by `fs_interfaces::forms`; draft: PLAN-quelle-und-abgleich section 3). Three kinds of lines (form, channel, relation), `#` starts a comment:
#   form line:    name@Major.Minor.Patch | display name | status | description        (status: stable | planned)
#   channel line: > channel | art | required | count                            (belongs to the form line above it)
#   relation line: = interval start end [all-day]  |  = parent channel      (after the channels of the form; see "Paket F" below)
# required: `!` = required, `-` = optional. count = how many fields a module maps onto the channel: `1`, `0..1`, `0..4`, `0..n`, `1..n` (never `?`: the reader refuses it; a required channel starts at 1).
# art: one of records text number flag time reference command (the seven basic kinds), or a set `text|number|time|flag` (no spaces, no duplicate, not empty): the field may have any art of the set. The reader refuses any other word. The reader holds the fixed table art -> allowed fs-types basic types.
# Rule "repeated value" (CIC-B): a channel the comment of its form marks `repeats` carries one `Value` per item with the same `path`; every other channel at most one (see cards-in-columns@1.4.0 and single-record@1.2.0).
# Versions (SemVer 2.0.0, three parts, read with the crate `semver`, no pre-release or build): Minor = an optional channel comes; Major = a channel goes or changes meaning; Patch = no change of the interface (text, docs, display name), never raised. A need on a form is written `name@<req>` (e.g. `tiles@^1.0.0`), a form itself `name@x.y.z`. Only append, never rename or remove.

#   Channels and standards (read in the text, 24.11.2026; every channel that has no line here is own and open):
#     start, end: art `time` = a point in time, written by the module as RFC 3339 section 5.6 `date-time` (ISO 8601 profile, https://www.rfc-editor.org/rfc/rfc3339); local calendar time with a zone is the module's job (JSCalendar, RFC 8984), the block shows what it is given. `all-day` (flag): the span covers whole days (RFC 3339 `full-date`, RFC 5545 DATE value).
#     depends: art `reference`, 0..n = the items this one depends on or follows. DIRECTION: `depends` of an item lists its PREDECESSORS (like DEPENDS-ON), but the temporal RELTYPEs stand in the predecessor and refer to the successor, so the module REVERSES them when it fills `depends`. The kind of relation is not a channel of this version: the module maps `DEPENDS-ON`; a finer kind would be an optional channel (minor).

# CIC-B (24.11.; source: woche-11-23/decisions/ENTSCHEID-cards-1-4-0.md section (a), (b)). Appended only: cards-in-columns@1.3.0 above stays as it is.

# Minor 1.4.0: the channels of 1.3.0 plus three, all optional. `lane` keeps its meaning (the board of the card); no lane-list channel, no `#n`.
#   state = JSCalendar `progress` (RFC 8984 section 5.2.5): a word, the five of the RFC (`needs-action`, `in-process`, `completed`, `failed`, `cancelled`) or a vendor word of the form `<domain>:<name>`. #   assignee = the person in charge: art `reference`, the IRI of the person (one person = one record in the people module; the name comes from there, never from this channel). REPEATS: see the rule below. A card without a person has no `assignee` value (a lane "nobody" is named by the frontend).
