# Form catalog (ADR 0068 style, read by `fs_interfaces::forms`; draft: PLAN-quelle-und-abgleich section 3). Two kinds of lines, `#` starts a comment:
#   form line:    name@Major.Minor.Patch | display name | status | description        (status: stable | planned)
#   channel line: > channel | art | required | count                            (belongs to the form line above it)
# required: `!` = required, `-` = optional. count = how many fields a module maps onto the channel: `1`, `0..1`, `0..4`, `0..n`, `1..n` (never `?`: the reader refuses it; a required channel starts at 1).
# art: one of records text number flag time reference command (the seven basic kinds), or a set `text|number|time|flag` (no spaces, no duplicate, not empty): the field may have any art of the set. The reader refuses any other word. The reader holds the fixed table art -> allowed fs-types basic types.
# Versions (SemVer 2.0.0, three parts, read with the crate `semver`, no pre-release or build): Minor = an optional channel comes; Major = a channel goes or changes meaning; Patch = no change of the interface (text, docs, display name), never raised. A need on a form is written `name@<req>` (e.g. `tiles@^1.0.0`), a form itself `name@x.y.z`. Only append, never rename or remove.

#   Range (time window): NOT a channel. It comes as the parameter `scope` of `FormSource.page` (formsource.capnp `page @1`: "a board, a group, a time range; its meaning belongs to the module"); the module expands series (contract `events`, occurrences), never the block. The counts `0..n` of depends and `0..1` of the others are proposals of 5d-3 (the sources only say "offen").
#   Channels and standards (read in the text, 24.11.2026; every channel that has no line here is own and open):
#     start, end: art `time` = a point in time, written by the module as RFC 3339 section 5.6 `date-time` (ISO 8601 profile, https://www.rfc-editor.org/rfc/rfc3339); local calendar time with a zone is the module's job (JSCalendar, RFC 8984), the block shows what it is given. `all-day` (flag): the span covers whole days (RFC 3339 `full-date`, RFC 5545 DATE value).
#     depends: art `reference`, 0..n = the items this one depends on or follows. Standard: iCalendar RELATED-TO (RFC 5545 section 3.8.4.5) with the RELTYPE values of RFC 9253 (https://www.rfc-editor.org/rfc/rfc9253): section 5 `DEPENDS-ON` ("the current calendar component depends on the referenced calendar component", e.g. a task blocked by another) and section 4 the temporal relations `FINISHTOSTART`, `FINISHTOFINISH`, `STARTTOFINISH`, `STARTTOSTART` (the property stands in the PREDECESSOR and refers to the SUCCESSOR; the GAP parameter, section 6.2, is the lead/lag). DIRECTION: `depends` of an item lists its PREDECESSORS (like DEPENDS-ON), but the temporal RELTYPEs stand in the predecessor and refer to the successor, so the module REVERSES them when it fills `depends`. The kind of relation is not a channel of this version: the module maps `DEPENDS-ON`; a finer kind would be an optional channel (minor).
#     lane, state, label, progress, move: own and open (no standard names them); lane and state are art `text` here (the draft calls them "grouping", but `grouping` is not one of the seven arts; a free grouping label is text); `move` is a command of the module (`events.update`, `planning.move`).

#   Workflow run (P-WORKFLOW-SICHT, K:43): items = step, label = step name, start/end = START/ENDE of the run list, depends = order of steps, state = run verdict, lane = workflow/role.

# Standards, READ in the texts on 24.11.2026 (the numbers below are the ones seen in the text; where a standard names no section number for a thing, none is given):
#   JSON Schema Validation, draft 2020-12 (https://json-schema.org/draft/2020-12/json-schema-validation): section 6.1.1 `type`, 6.1.2 `enum`, 6.2.2 `maximum`, 6.2.4 `minimum`, section 9.1 `title` and `description`, 9.2 `default`, 9.4 `readOnly` ("managed exclusively by the owning authority"; an attempt to change it is ignored or rejected).
#   HL7 FHIR R5 Questionnaire (https://hl7.org/fhir/R5/questionnaire.html, resource page section 2.5): `Questionnaire.item` with `linkId`, `text`, `type` (group, display, question, boolean, decimal, integer, date, dateTime, time, string, text, url, coding, attachment, reference, quantity), `initial`, `readOnly`, `answerOption`; the ANSWER is not in the Questionnaire but in the resource QuestionnaireResponse; `initial` is not allowed on a group (rule que-8).
#   W3C Model for Tabular Data and Metadata on the Web, CSVW (https://www.w3.org/TR/tabular-data-model/): section 4.3 Columns (annotations `titles`, `name`, `datatype`, `required`), 4.4 Rows (`titles`, `primary key`, `number`), 6.5.2 Column and row labelling (a row is named by its `titles`, else by its primary key cells, else by its number).
#   ActivityStreams 2.0 Vocabulary (https://www.w3.org/TR/activitystreams-vocabulary/): section 4 Properties `name`, `summary`, `content`, `mediaType`, `icon`, `image`, `updated`; types `Object`, `Article`, `Note`, `Image`.
#   AppStream upstream metadata (https://www.freedesktop.org/software/appstream/docs/chap-Metadata.html, generic component): the tags `<name/>`, `<summary/>`, `<description/>`, `<icon/>`, `<screenshots/>`.
